## 五、现有领域模型（照抄 `static/studio/types.ts`）

```ts
type Project = {
  version: 1; id: string; name: string;
  drawing: Drawing | null; calibration: Calibration;
  regions: Region[]; walls?: Wall[]; openings?: WallOpening[];
  wallHeight?: number;      // cm
  wallThickness?: number;   // cm
  additionalCost: string; taxRate: string;
  view: { labels: boolean; drawingOpacity: number };
  materialsSnapshot?: Material[];
};

type Region = {
  id: string; name: string; points: Point[]; holes: Point[][];
  hidden: boolean; items: QuoteItem[]; additionalCost: string;
  source?: 'walls'; sourceKey?: string; wallIds?: string[];
};

type QuoteItem = {
  id: string; materialId: string; materialName?: string; unit?: string;
  unitPrice: string; wasteRate: string; laborRate: string; additionalCost: string;
  quantityMode: 'area' | 'perimeter' | 'manual'; quantity: string;
  provenance?: { source: string; sourceUrl?: string; region?: string; priceDate?: string; spec?: string; supplier?: string; updatedAt?: string };
};
```

- `Wall`（`lib/wall-plan.ts`）：`{ id, start:{x,y}, end:{x,y}, thickness:number /*cm*/, height:number /*cm*/ }`，长度按中心线，坐标单位是米（图纸坐标换算后）。
- `WallOpening`（`lib/wall-solid.ts`）：类型 `门 | 窗 | 孔洞`，宽高 cm、距墙起点 cm、离地 cm、形状（矩形/椭圆/多边形）。

## 六、计价内核的用法（必须复用，不要另写一套）

`lib/pricing.js` 的导出：

- `normalizeDecimal(value, label, {min,max})`：校验并规范化十进制字符串。
- `formatMoney(value)` / `formatQuantity(value, places)`：格式化。
- `calculateProject(project)` 返回：
  ```js
  {
    projectId, name, currency:'CNY', status:'ready'|'pending', pending, pendingReasons[],
    regions: [...], walls: [...],
    materialCost, laborCost, additionalCost, projectAdditionalCost,
    subtotal, beforeTax, taxRate, tax, total   // 均为字符串，单位元，两位小数
  }
  ```
- **所有金额必须走 BigInt 定点运算**（`decimal / multiply / divide100 / cents / money` 这套内部函数），禁止用 `Number` 做钱的加减乘除，禁止 `toFixed`。
- 金额字段存成字符串，出口统一 `formatMoney`。

`lib/export.js` 的导出：`projectToCSV(project, options)`、`renderExportHTML(project, options)`、`downloadCSV`、`printQuote`、`downloadBlob`。新增造价表导出请沿用同样的风格（BOM 头、CRLF、`csvCell` 转义）。

## 七、硬约束

1. **不新增依赖**：不装 npm 包、不装 pip 包、不引入 CDN、不联网请求。现有依赖只有 typescript + playwright。
2. **不破坏现有功能**：`npm.cmd test` 的 121 项、五个 e2e 必须继续通过。
3. **中文界面**，术语用国内工程口径：分部分项工程、措施项目、其他项目、规费、税金、综合单价、工程量、项目特征。
4. **估算必须标注**：任何按指标推算的量（钢筋含量、水电管线长度、桥梁指标）必须在页面、CSV、打印页上显示"估算"字样，不能伪装成精算。
5. **不编造单价**：默认单价只能是"参考值（需按当地信息价替换）"，或留空并在界面上高亮提示填写。不许把网上看来的数字当权威价格写死。
6. **向后兼容**：新增字段一律可选；旧项目 JSON 必须能打开、能算、能导出。`validateProject` 需要同步放行新字段。
7. **撤销/重做、自动保存、导出**继续工作：所有改项目的动作走现有 `update()` / `changeWalls()` 一类入口，不要绕过历史栈。
8. **算量是纯函数**：新增的计算逻辑放 `static/studio/lib/`，不碰 DOM、不读全局状态，输入项目数据，输出构件/工程量数组，便于单测。
9. **不要手改编译产物**：只改 `.ts`；`static/studio/*.js` 由 build 生成。
10. **不要删改无关文件**：不重构现有模块，不改 `GEstimator-2.7/`、`openPlan3D-main/`、`development_resources/`。
