# 提示词 50：三模块合并与总体验收（最后跑）

> 用法：先贴 `00_共享上下文.md`，再贴本文件。前提：`05` 骨架 + `10/20/30` 三个模块至少各完成一个可运行版本。

## 任务

把土建、装修、市政三个模块合并成**一张总造价表**，做兼容性、性能、导出、文档与端到端验收。这一步不加新功能，只做整合与打磨。

## 一、合并前先检查

1. 三个模块是否都通过 `registerCostModule()` 注册，而不是各自改 `app.ts`？
2. 是否都写 `project.cost.modules.<id>`，而不是各加一个顶层字段？
3. 是否都复用 `lib/cost.ts` 的 `CostItem` 与 `summarize()`，而不是各算各的税？
4. 项目编码是否撞号（三个专业都用 `0105...` 就会撞）？

任何一条不满足，先重构到统一契约，再往下做。

## 二、总造价表

在「汇总」页签实现三级结构：

```
一、分部分项工程费
    1. 土建            ¥ xx
    2. 装饰装修        ¥ xx
    3. 市政            ¥ xx
二、措施项目费          ¥ xx（默认 2.5%，可改）
三、其他项目费          ¥ xx（默认 0，可加暂列金额）
四、规费税金            ¥ xx（默认 9%）
─────────────────────────────
含税总价               ¥ xx
```

要求：

- 每个专业可展开到分部分项明细，点一行能跳到对应专业页签并高亮。
- 顶部显示"含 N 项估算"，点击可筛出所有 `estimate: true` 的行。
- 汇总口径与单专业页签里的数字必须完全一致（同一个 `summarize()`）。
- 空项目（三专业都没生成）显示引导："先在土建/装修/市政生成清单"。

## 三、导出

1. **总表 CSV**：一张表，列 `序号,专业,项目编码,项目名称,项目特征,单位,工程量,综合单价,合价,是否估算,备注`，末尾追加五个汇总行。
2. **分专业 CSV**：每个模块单独导出。
3. **打印**：A4 纵向，表头重复，页脚"第 X 页 / 共 Y 页" + "本表为方案估算"。
4. 文件名：`项目名-造价表-YYYYMMDD.csv`，项目名里的非法字符要替换。

## 四、兼容性

1. 用旧版本导出的项目 JSON（没有 `cost` 字段）打开，软件不能报错，进入造价页显示空态。
2. 新版本保存后，再用旧版本打开（若可能）不能崩——新字段必须是可选的。
3. `validateProject` 要能接受 `cost` 字段，同时不放松原有校验。
4. 撤销/重做：生成造价不进入撤销栈（它是派生数据），但修改单价要进入。

## 五、性能

- 100 个房间 + 1000m 道路：`calculate` 总耗时 < 300ms（用 `performance.now()` 在控制台打印）。
- 造价表渲染 500 行不卡顿：用文档片段一次性插入，避免逐行 append。
- 参数改动只重算本专业，不触发另外两个。

## 六、端到端验收脚本

新建 `tests/cost.e2e.mjs`（playwright，参照 `tests/studio.e2e.mjs` 的启动与隔离方式）：

1. 启动服务 → 打开首页 → 画一个 6×4 房间。
2. 点「造价」→ 土建 → 生成 → 断言出现"矩形柱""有梁板"。
3. 切装修 → 一键精装 → 断言出现"块料楼地面""踢脚线"。
4. 切市政 → 输入长度 200 → 生成 → 断言出现"检查井"。
5. 回汇总 → 断言总价 = 三专业之和 + 措施费 + 税金（用页面上的数字复算）。
6. 导出 CSV → 读回 → 断言行数与列数。
7. 保存 → 刷新 → 重新打开 → 数字一致。
8. 截图到 `artifacts/cost-*.png`。

## 七、文档

1. `README.md`：功能清单加三行（土建/装修/市政），说明"方案估算"定位。
2. `docs/` 增加索引 `docs/cost.md`：总览 + 三个模块文档的链接。
3. `docs/client-user-guide.html`：加一节"从户型到总造价：五步走"。
4. 已知限制集中写一节，三条必须写：

   - 钢筋、水电、桥梁是指标估算；
   - 不能替代施工图预算与招标控制价。
