# 提示词 10：土建模块（主体结构）

> 用法：先贴 `00_共享上下文.md` 全文，再贴本文件。依赖 `05_造价平台骨架.md` 已经完成（`lib/cost.ts` 与 `registerCostModule` 已存在）。若骨架还没做，先做骨架。

## 任务

在现有平面（墙体/房间）基础上，一键生成**主体结构方案**（基础、柱、梁、板、墙）和**土建造价表**。用户只填 5 个参数、点两次按钮。

范围明确：这是**方案估算**，不是结构设计。不做荷载计算、不做配筋设计、不出施工图。所有由指标推算的量必须在界面和导出里标「估算」。

## 一、用户看到的三步

1. 顶部点「造价」→ 切到「土建」页签 → 一张参数卡，默认值已填好：
   - 结构形式：框架 / 砖混 / 框架-剪力墙（默认框架）
   - 地上层数：3（1–30）
   - 层高：3.0 m（2.4–6.0）
   - 基础形式：独立基础 / 条形基础 / 筏板基础（默认独立基础）
   - 混凝土强度：C30（C25/C30/C35/C40）
   - 高级参数（默认折叠）：柱截面、板厚、基础埋深、钢筋含量指标、抗震等级
2. 点「生成结构」→ 依据平面外轮廓自动布柱网（跨数可调），生成构件，页面显示：
   - 一个小平面示意（SVG 画柱网 + 外轮廓）
   - 构件汇总表（柱 N 根、梁 M 根、板面积…）
   - 工程量表（土方、混凝土、模板、钢筋、砌体、脚手架）
3. 点「生成造价表」→ 清单项写入统一 `CostItem[]`，跳到造价表，可逐行改单价，可导出。

若用户还没画平面图，参数卡里提供「按矩形快速生成」：输入长 × 宽（m），当作单层外轮廓。

## 二、数据模型（写进 `project.cost.modules.structure`）

```ts
type StructureConfig = {
  system: 'frame' | 'masonry' | 'frame-shear';
  floors: number;            // 地上层数
  floorHeight: number;       // m
  foundation: 'spread' | 'strip' | 'raft';
  concreteGrade: 'C25' | 'C30' | 'C35' | 'C40';
  columnSize: number;        // mm，默认 400
  slabThickness: number;     // mm，默认 110
  embedDepth: number;        // m，基础埋深，默认 1.5
  rebarIndex: number;        // kg/m²，默认 50
  gridX: number;             // X 向跨数，默认按 6m 跨度自动取整
  gridY: number;
};

type StructureModel = {
  config: StructureConfig;
  footprint: { width: number; height: number; area: number };  // 标准层外轮廓，m
  columns: { x: number; y: number; size: number }[];            // 柱网交点
  quantities: StructureQuantities;   // 见第三节
  estimateFlags: string[];           // 哪些量是估算，如 ['钢筋','内墙','土方']
};
```

可选字段，旧项目没有 `cost` 也能正常打开。每次改参数重算并覆盖 `structure`，同时重新生成 `CostItem[]`。

## 三、算量规则（按这个来，不要自创）

符号：`A` = 标准层外轮廓面积（m²），`n` = 层数，`h` = 层高，`t` = 板厚。

| 分项 | 公式 | 说明 |
| --- | --- | --- |
| 建筑面积 | `A × n` | 外轮廓水平投影 × 层数 |
| 平整场地 | `A` | m² |
| 基坑开挖 | 棱台公式 `V = H/3 × (S下 + S上 + √(S下·S上))`，`S下=(L+0.6)(W+0.6)`，`S上=(L+0.6+0.66H)(W+0.6+0.66H)`，`H = 埋深 + 0.1` | 放坡 1:0.33，工作面 0.3m 每边 |
| 回填方 | `V挖 − V基础 − V垫层` | m³ |
| 余方弃置 | `V挖 − V回填` | m³ |
| 垫层 | `n基础 × 基底面积 × 0.1` | C15 |
| 独立基础 | `n基础 × 1.5×1.5 × 0.5`（尺寸随柱截面放大） | 每柱一个 |
| 条形基础 | `基础长 × 宽 0.8 × 高 0.4` | 沿外墙 |
| 筏板基础 | `A × 0.4` | 满堂 |
| 矩形柱 | `柱数 × b×b × (h − t) × n` | b 取 `columnSize/1000` |
| 矩形梁 | 主梁 `0.25 × (L/10) × L`；次梁 `0.2 × (L/12) × L`；主梁沿两向柱网，次梁按主梁长度的 1.2 倍 | 梁高按跨度估 |
| 有梁板 | `A × t × n`（扣柱体积） | 板厚按跨度取 100–130 |
| 砌体墙 | `(外墙长 + 内墙长) × (h − t) × 0.2 − 洞口体积` | 内墙长按 `A/层高 × 0.5` **估算** |
| 柱模板 | `柱周长 × 柱高 × 柱数` | m² |
| 梁模板 | `(2×梁高 + 梁宽) × 梁长` | m² |
| 板模板 | `A × n + 周边侧模` | m² |
| 墙模板 | 仅混凝土墙时计算 | m² |
| 钢筋 | `rebarIndex × 建筑面积 / 1000` | **吨**，指标估算 |
| 综合脚手架 | `建筑面积` | m² |
| 垂直运输 | `建筑面积` | m² |

单位一律：混凝土/土方/砌体 `m³`，模板/脚手架 `m²`，钢筋 `t`，场地 `m²`。

## 五、单价从哪来（重要）

不得编造市场价。做法：

1. 每个清单项带一个**参考单价区间**（只作为默认值，存成"参考值"），例如 C30 混凝土 480–560 元/m³、模板 45–65 元/m²、钢筋 4200–4800 元/t、砌体 380–450 元/m³。
2. 界面上单价列可编辑，首次生成时在顶部黄色提示条写："单价为参考值，请按当地信息价替换后使用"，并在 `CostItem.note` 写 `参考值，未取当地信息价`。
3. 如果材料库（`lib/materials.ts` / 后端 `data/app.db`）里已有对应材料价格，优先用材料库的价，并在 `note` 写来源与价格日期。

## 六、界面细节

- 参数卡用现有 `panels.ts` 的输入样式（`.field` / `.row` 一类），别引入新框架。
- 参数变化不立即重算，点「生成结构」才算（避免大项目卡顿）；但改单价要即时重算合价。
- 生成后用 `toast()` 提示："已生成 3 层框架结构，共 12 根柱、28 根梁，含 2 项估算"。
- 平面示意用内联 SVG，尺寸 320×240，按外轮廓等比缩放，柱点画方块。
- 页签内提供「清空本专业」按钮（带确认）。

## 七、测试

新建 `tests/structure.test.mjs`：

1. 10×10 m 单层、层高 3m、板厚 110：建筑面积 100 m²，板混凝土 11 m³（±0.1）。
2. 柱体积：400×400、净高 2.89、4 根 → 1.85 m³（±0.01）。
3. 模板面积与混凝土体积的量级关系合理（柱模板 ≈ 4×0.4×2.89×4）。
4. 层数从 1 改 3，混凝土与钢筋近似 ×3（±1%）。
5. 0 层 / 负数 / 层高超限 → 抛 `RangeError`，界面给中文提示。
6. 基准：同一输入两次生成，结果完全一致（无随机）。

## 八、边界（写进 docs）

不做：结构计算、抗震验算、配筋图、基础沉降、地下室、人防、钢结构、装配式、屋顶、楼梯（可作为可选项，但默认不计）。不做斜墙、异形柱。结果只能用于方案比选与投资估算，不能作为施工依据。
