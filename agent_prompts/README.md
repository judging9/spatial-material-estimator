# 给 AI Agent 的提示词包（土建 / 装修 / 市政）

这个目录是给编码 Agent 用的提示词，不是给软件用的。用法：把文件内容复制到 Agent 的对话框里。

## 文件与执行顺序

| 顺序 | 文件 | 作用 | 预估工作量 |
| --- | --- | --- | --- |
| 0 | `00_共享上下文.md` | 项目现状、技术栈、数据模型、硬约束。**每次都先贴** | — |
| 1 | `05_造价平台骨架.md` | 建统一清单结构 + 造价工作台 + 汇总导出（空表） | 1 个会话 |
| 2 | `10_土建模块.md` | 基础/柱/梁/板/墙 + 土方 + 模板 + 钢筋 | 1–2 个会话 |
| 3 | `20_室内装修模块.md` | 做法包 + 地面/墙面/天棚/门窗/水电 | 1–2 个会话 |
| 4 | `30_市政模块.md` | 道路/管网/路灯/绿化/桥梁 | 1–2 个会话 |
| 5 | `50_合并验收.md` | 总表、兼容、性能、e2e、文档 | 1 个会话 |

`10/20/30` 互不依赖，可以三个会话并行跑，但必须等 `05` 完成之后再开始，否则契约不存在，三个 Agent 会各写一套。

## 怎么用

1. 新开一个 Agent 会话，工作目录设为 `D:\c\yujiao_project`。
2. 先贴 `00_共享上下文.md` 全文，再贴对应模块文件全文。
3. 让 Agent 先输出实施计划（10 行以内），确认后再动手。
4. 每个模块做完，先跑 `npm.cmd run build` + `npm.cmd run typecheck` + 单测，再让它汇报。
5. 三个都做完，最后跑 `50_合并验收.md`。

如果 Agent 支持多轮，可以在同一会话里连续做，但**不要**把三个模块塞进一个提示词——上下文会糊，它会把三个模块写成三套重复代码。

## 为什么这样拆

- **先定契约**：三个模块最大的风险不是算量算错，是各写一套表、各算一次税，最后合不起来。`05` 就是先把 `CostItem` 和 `summarize()` 钉死。
- **算量是纯函数**：所有公式放 `lib/`，不碰 DOM，这样能单测，Agent 也不容易把逻辑写进事件回调里。
- **复杂度分级**：土建最容易出错（公式多、量级大），装修最容易重复计价（找平/防水/面层分不清），市政最容易漏项（围挡、沟槽、井）。
- **用户操作简单**：每个模块都规定成"填 3–6 个参数 → 点一次生成 → 可改单价"，不让用户去点几十个构件。

## 三个模块各自最容易翻车的地方

**土建**：Agent 会把"混凝土体积"和"模板面积"算混；会把钢筋按体积乘一个拍脑袋的系数；会忘记扣板厚导致柱高超标。提示词里给了公式表，让它照着填。

**装修**：Agent 会让"地砖"项包含找平，然后找平再列一次，总价虚高 30%。提示词里用 `includesBase` 和"防重复计价的硬规则"卡住。

**市政**：Agent 会只算管道长度，忘掉检查井、沟槽土方、回填、余方外运、围挡。这五项往往是市政造价的大头。

## 提示词的写法约定

- 每条公式都给了符号定义和默认值，Agent 不用猜。
- 每个模块都规定了数据存哪（`project.cost.modules.xxx`），避免污染顶层模型。
- 都要求"参考单价 + 可编辑 + 标注"，堵住编造价格的嘴。
- 都写了"不做"清单，防止 Agent 自由发挥去做结构计算、管网水力计算。

## 一个短版总纲（如果你想一次说清）

> 读 `D:\c\yujiao_project\agent_prompts\` 下的文件，按 `00 → 05 → 10 → 20 → 30 → 50` 顺序执行。每个文件开头都有"用法"，照着做。每个模块完成后必须跑 build、typecheck、单测，并把结果贴给我。不要改 `GEstimator-2.7/`、`openPlan3D-main/`、`development_resources/`，不要新增依赖，不要编造单价。

## 验收时自己看什么

1. 打开软件点「造价」，三个页签都在，都能生成。
2. 随便改一个房间面积，工程量跟着变，总价跟着变。
3. 导出的 CSV 用 Excel 打开不乱码，列对齐，汇总行在最后。
4. 估算项有黄色标记，打印页也有。
5. 关掉重开，数据还在。

## 已知前提

- 当前软件是单层平面模型（没有楼层概念）。土建模块的"层数"是参数化的标准层复制，不是真的多层建模。这是刻意的简化，写进了土建提示词的边界里。
- 现有项目没有"构件"概念，只有墙和房间。三个模块生成的构件是**算量模型**，不进入三维视图。如果以后要三维显示梁柱，那是另一个任务。
- 价格来源仍然是现有的材料库（统计局 + 地方信息价导入 + 手工）。三个模块的默认单价是参考值，必须替换。
