# OpenPlan3D 与低门槛绘图集成

本次改进让用户直接绘制有实际尺寸的墙线，闭合后生成可编辑房间，再选材料和计算报价。也保留按净尺寸创建房间模板的快捷流程。继续使用现有 Python 服务、TypeScript Canvas 工作台及独立几何、计价、保存和导出模块。

## 源码来源与选择

用户提供的源码位于 `openPlan3D-main/openPlan3D-main/`，包内版本为 `0.9.0`，采用 MIT 许可，版权为 `Copyright (c) 2026 theLodgeStudio`。完整归属和许可见 [第三方通知](../THIRD_PARTY_NOTICES.md#openplan3d-二维绘图参考与改编)。

OpenPlan3D 使用 SvelteKit、Svelte 5、TypeScript、Three.js 和 Tailwind CSS。其模型将墙体、门窗和房间分开：墙体提供有实际尺寸的端点和厚度，门窗挂在墙体上，房间从墙体拓扑计算。这种结构对后续完整平面图编辑有帮助。

本次复用房间预设、吸附交互和墙体拓扑中的纯逻辑部分：

| 来源 | 本次使用方式 |
| --- | --- |
| `src/lib/utils/roomPresets.ts` | 矩形、L 形等房间轮廓的生成思路；改为显式净尺寸和当前 `Region` 数据 |
| `src/lib/utils/canvasInteraction.ts` | 网格、端点及方向吸附规则；适配当前画布坐标与缩放 |
| `src/lib/utils/roomDetection.ts` | 实际复制并改编墙端点、T 接点、交叉点和房间面的拓扑检测 |
| `src/lib/utils/roomNesting.ts` | 实际复制并改编内圈孔洞的层级判断 |
| `src/lib/utils/wallProfiles.ts` | 复制其无框架依赖的墙段几何，裁剪配套类型依赖 |
| `src/lib/utils/interiorArea.ts` | 墙厚扣除的计量参考；本项目另实现净施工多边形，既用于画布也用于报价 |

`roomPresets.ts` 原文件还引用 OpenPlan3D 的 Svelte stores，不能原样导入当前应用。本次将纯几何与其 UI、状态管理解耦，并继续使用当前报价与撤销历史。

## 本次交互范围

- 可以从空白平面图开始，连续绘制水平或垂直墙线；闭合墙线形成房间，共墙分隔和 T 接点可以形成多个房间。
- 结构化墙线使用已知实际单位，不依靠图像猜测面积；也可用房间模板输入实际净尺寸。
- 墙端点和墙上连接点自动吸附；房间边界由墙体维护，选择墙线修改尺寸。自动生成的房间不能独立拖动顶点，以免脱离墙体。
- 房间共享边界允许相邻排列，净区域相互重叠必须被拒绝，避免重复统计面积。
- 房间几何继续生成当前工作台的可编辑多边形，并接入材料、损耗、人工、附加费和税费计算。
- 原来的上传图片、两点校准、手绘多边形与封闭白区候选识别仍使用其原流程。

本阶段为当前工作台的绘图扩展，**不是将整套 OpenPlan3D 嵌入网页**。不包含它的 Three.js 三维编辑器、家具资源、Apple RoomPlan 扫描或云端服务，也不将它的全部功能标为本项目已实现。

## 尺寸与面积约定

模板输入单位为米，表示室内施工边界的净尺寸。新建模板有已知实际坐标，画布缩放仅改变显示大小，不改变实际尺寸。

矩形房间的面积为：

```text
净面积 = 净宽 × 净深
```

当前界面的快捷模板为矩形。L 形可通过连续绘制正交墙线形成；纯逻辑房间生成模块也已提供显式缺口宽深，但尚未开放为界面模板。L 形净轮廓保留真实凹口，不按外包矩形冒充面积。

```text
净面积 = 外包净宽 × 外包净深 − 缺口宽 × 缺口深
```

这些公式用于说明和验收，实际报价仍以生成后的净多边形坐标计算。墙体修改和模板创建都通过几何有效性及重叠检查。原图手绘区域继续支持顶点编辑和孔洞修改。界面显示的两位小数用于阅读，计价使用未按显示精度提前截断的几何面积。

## 原图识别仍需人工判断

OpenPlan3D 的房间检测基于已有结构化墙线，不会自动理解原始户型照片。本次模板和吸附功能也不意味着系统能从低清 JPG 中自动读出墙体、门洞、文字和尺寸。

例如 `examples/示例1.jpg` 仍需要用户根据尺寸标注校准并描绘，或直接按标注尺寸重建房间。当前图片识别只能提供实际像素中的封闭白区候选，不能作为房间语义或实际尺寸的确认结果。

## 当前墙线引擎与后续范围

墙线引擎位于 `static/studio/lib/wall-plan.ts`，坐标和墙厚使用厘米。`detectPlanRooms` 复用 OpenPlan3D 的墙体图并追踪闭合面，再将外轮廓按每条墙的半厚向内偏移，将内部闭合圈按半墙厚向外扩为扣除孔洞，返回真实净施工多边形。

引擎会用现有几何模块检查返回轮廓、孔洞和区域重叠，还会检查净区域是否与任一墙体占地相交。不能可靠扣墙厚时明确报错，不返回墙中心线面积冒充施工净面积。实际断口不会因为原源码的 5 cm 自动连接容差被补成房间；本项目将其改为数值容差，连接由用户的吸附绘图完成。

当前支持正交墙、共墙、T 接点、墙线交叉和独立内圈。内墙死端、过窄的净通道、同一直边上的墙厚突变等复杂情形暂不支持可靠净轮廓，应先补齐或调整墙线。斜墙和曲墙明确拒绝，门窗对象与完整三维编辑尚未接入。

后续完整墙体和门窗编辑仍需处理：

1. 墙体端点、T 接点、交叉点和共享墙的拓扑；门窗挂在墙上，不能导致房间边界意外断开。
2. 明确图纸尺寸是墙中心线、墙外边还是室内净边，避免同一尺寸采用不同计量约定。
3. 扣除墙体厚度和墙体占地的并集，并生成可编辑的净施工轮廓；孔洞和相邻房间不能重复扣除或计入。
4. 墙体修改后保持房间、材料报价和历史记录的关联，不能按房间名称随意匹配。

OpenPlan3D 的 `room.area` 是墙中心线围合面积，而且已按界面精度舍入，不能直接作为施工净面积。例如 `4 × 3 m` 的墙中心线矩形、墙厚 `0.2 m` 时，中心线面积为 `12 m²`，室内净面积为 `10.64 m²`。当前墙线引擎已通过这一净多边形测试；界面的矩形快捷模板输入净长净宽。这两个输入口径明确区分。

墙线模块回归测试在 `tests/wall-plan.test.mjs`，涵盖真实净面积、T 接三房、交叉四房、反向重复共墙、断口、内圈孔洞、凹房间、墙厚变化、无效数据和缩放下的吸附行为。
