# 市政场地几何与计量依据

本轮查阅了 `development_resources` 中的 QGIS 与 GDAL 源码，参考其显式控制线缓冲端帽、接角与米制坐标的处理方式。

- `QGIS-master/QGIS-master/src/core/geometry/qgsgeos.cpp` 的 `QgsGeos::buffer`（约 2446 行）与 `QgsGeos::offsetCurve`（约 3381 行）明确传递缓冲距离、端帽、接角和 miter limit，避免把路线外包矩形当道路面积。
- `gdal-master/gdal-master/ogr/ogrgeometry.cpp` 的 `OGRGeometry::BufferEx`（约 5060 行）区分 `ENDCAP_STYLE`、`JOIN_STYLE` 和 `MITRE_LIMIT`，并拒绝非法参数。

市政模块采用原创 TypeScript 实现，使用本项目已有纯多边形引擎，不复制上述 GPL 源码，也不要求用户安装 GIS 或 GEOS。路线采用平齐端帽，转角使用受限 miter / bevel；宽度造成自交时明确拒绝，提示缩小宽度或修改路线。

## 工程量口径

原生市政画板坐标使用 cm。上传图片的 XY 坐标仍是图片坐标，必须使用用户校准的 `metersPerPixel` 换算；路宽、层厚、高程等输入始终按 cm。相机与画布缩放不参与计量。

- 道路：将实际中心折线偏移成完整路宽轮廓，采用该轮廓面积。道路与铺装、绿化的同标高交叠部分，按持久化的放置顺序分配实际净轮廓，确保一份场地不重复收费。完全重叠的后放置对象净量为 0；更改单价、UUID 或数量不会改变几何归属。
- 铺装 / 绿化：按多边形净面积计量，内部孔洞真实扣除。支持不规则凹形边界，孔洞中的独立区域不被外区重复扣减。
- 主铺装体积：净面积 × 用户填写的主铺装厚度。附加结构层单独按面积，或净面积 × 该层厚度计价；主层与附加层不重复收费。
- 市政管线：按 XY 实际距离与逐点 Z 高程的三维线段长度计米，垂直段也计入。选择体积计价时，使用水平路线投影长度 × 用户矩形沟宽 × 沟深，并明确标记为管沟开挖估算；不推测地形、放坡或井坑。
- 路缘石：按实际路线计米，或按照路宽与高得到路缘石外形体积。
- 检查井 / 路灯：按用户确认的件数填写价格，不将井体外包体积或灯杆包围体积当作砌筑或钢材净用量。

市政对象是独立场地数据，保持在项目根级，不随建筑楼层复制或重复累计；材料采购量包含损耗，人工按净工程量计算，元素固定费用、结构层固定费用以及共享项目附加费、税金各计一次。市政预算不自动再叠加旧市政指标清单或室内装修预算。

单价全部由用户填写。空价保持待填写，明确填写 0 为合法价格；未校准的几何用量保持待确认，已知按件报价及固定费用仍可显示。金额复用项目的十进制和整数分内核，避免浮点金额误差。

## 当前范围

这是本地米制场地设计与工程量预算，不提供地图坐标系、地形 DEM、纵断面或排水水力计算。当前道路、铺装、绿化使用统一标高；管线可逐点编辑高程。路径最多 200 节点、场地最多 500 对象。更多 GIS 格式与地形服务可后续接入，不能在缺少真实数据时伪造地形或自动估算施工量。
